**Status:** `APPROVED FOR FIRST IMPLEMENTATION — AUDIOVISUAL VALIDATION REQUIRED`  
**Product phase:** `Ambient Audiovisual Experience — v1.1.0`  
**Last updated:** 2026-09-28

# 1. Purpose

This document defines the first audiovisual implementation of **Static Mathematical Letter** after acceptance of the mobile-first Presentation & Experience Core v1.0.

The goal of v1.1.0 is deliberately modest:

> add music as an ambient narrative layer around the already working automatic experience without making music the master clock of the mathematical animations.

The current visual experience remains structurally valid.

v1.1.0 adds:

1. final minor presentation adjustments inherited from v1.0 validation;
2. a golden-thread glow;
3. a slower narrative rhythm;
4. one local audio asset;
5. a minimal `AudioController`;
6. an explicit user gesture to open the letter;
7. audio lifecycle tied to global autoplay;
8. approximate audiovisual alignment around the transition into Model A;
9. graceful fallback when audio cannot play.

This phase does **not** implement beat-level synchronization, mathematical time remapping, regional soundtrack mapping or a new audiovisual master timeline.

The intended result is:

\[
\boxed{
\text{existing experience}
+
\text{ambient music}
}
\]

not:

\[
\boxed{
\text{music}
\rightarrow
\text{mathematical timing}
}
\]

# 7. Audiovisual principle

The v1.1.0 timing relationship is intentionally loose.

The visual experience remains the master narrative sequence.

The audio accompanies it.

Conceptually:

```text
User gesture
    ↓
Audio starts at 0
    +
Experience starts at 0
    ↓
Existing cinematic sequence
    ↓
Approximate musical alignment
    ↓
Experience completes
    ↓
Audio stops/resets
```

There is no continuous synchronization loop comparing:

```text
audio.currentTime
```

with:

```text
graph progress
```

during normal playback.

The application does not speed up or slow down the visual experience to compensate for small timing drift.

```ts
export const audioConfig = {
  src: "/audio/background.mp3"

```

No external streaming service or runtime network dependency is required.

Audio rights/licensing management is outside the technical scope of this document.

# 9. Entry experience — “Abrir carta”

## 9.1 Requirement

v1.1.0 adds an explicit initial user gesture before the audiovisual journey begins.

The primary action is:

```text
Abrir carta
```

This is both:

- a narrative entry into the experience;
- the user gesture used to begin audible media playback reliably.

The control must not be presented as a technical permission dialog.

Avoid labels such as:

```text
Activar audio
Permitir sonido
Iniciar reproducción multimedia
```

The interface should preserve the letter metaphor.

## 9.2 Initial state

Before the user activates `Abrir carta`:

- viewport is at the beginning;
- graphs are reset;
- audio is idle;
- cinematic autoplay has not started;
- no automatic scrolling occurs;
- the page may show the opening composition;
- the experience waits for the explicit gesture.

The v1.0 behavior of automatically starting immediately on page load is superseded for normal v1.1 audiovisual mode.

## 9.3 Activation

Activating `Abrir carta` initiates, as one logical action:

```text
reset experience
reset audio
audio start from 0
start cinematic experience
```

Audio playback should be requested directly inside or immediately from the user-gesture call chain where practical.

# 10. Reduced motion entry

`prefers-reduced-motion: reduce` continues to override global autoplay.

In reduced-motion mode:

- no cinematic autoplay begins;
- no progressive graph animation begins;
- no cinematic scrolling begins;
- curves remain complete;
- navigation remains manual;
- mathematical disclosures remain available;
- background music does not automatically play.

`Abrir carta` may still dismiss/open the introductory presentation if required by the UI, but it must not override the reduced-motion contract by starting the cinematic sequence.

Because v1.1.0 defines music as part of autoplay, reduced-motion/manual mode does not receive automatic background music.

# 11. Minimal AudioController

Add an isolated audio module.

Recommended structure:

```text
src/
  audio/
    audio.controller.ts
    audio.config.ts
    audio.types.ts
```

Names may vary slightly if repository conventions justify it.

## 11.1 Responsibility

`AudioController` owns only the soundtrack lifecycle.

It must not know:

- mathematical time;
- mathematical parameters;
- graph geometry;
- Model A milestones;
- Model B timings;
- DOM scroll destinations;
- disclosure contents.

## 11.2 State

Recommended state:

```ts
type AudioState =
  | "idle"
  | "playing"
  | "paused"
  | "ended"
  | "blocked"
  | "error";
```

Equivalent naming is acceptable if semantics remain explicit.

## 11.3 Minimal public contract

Recommended interface:

```ts
interface AudioController {
  startFromBeginning(): Promise<void>;
  pause(): void;
  reset(): void;
  getState(): AudioState;
}
```

Optional:

```ts
onChange(listener: () => void): () => void;
```

may be added if useful for presentation or testing.

## 11.4 Native implementation

Prefer a native:

```text
HTMLAudioElement
```

or equivalent `<audio>` element.

Do not introduce Web Audio API complexity for v1.1.0.

# 12. Audio lifecycle

## 12.1 Start

When a complete autoplay journey begins:

```text
audio.currentTime = 0
↓
audio.play()
↓
experience begins from intro
```

The intended perceptual behavior is that music and the cinematic experience begin together.

No exact frame synchronization is required.

## 12.2 Autoplay OFF

When global autoplay is disabled:

```text
ExperienceController.disable()
```

must also result in:

```text
audio.pause()
```

Audio must stop progressing while the experience is in manual mode.

Do not continue soundtrack playback independently.

## 12.3 Manual graph controls

When a manual graph control cancels global autoplay:

```text
Play
Pause
Replay
```

the audio is paused as part of the same transition into manual mode.

The manually controlled graph does not restart or resume music.

Therefore:

```text
manual mode = no soundtrack
```

for v1.1.0.

## 12.4 Autoplay restart

When the user re-enables autoplay:

```text
reset graphs
reset disclosures
reset experience
return home
reset audio to 0
start audio
start intro
```

Audio never resumes from its previously paused timestamp after restarting global autoplay.

It starts from the beginning.

## 12.5 Completion

When the cinematic journey enters:

```text
COMPLETE
```

the audio must:

1. stop/pause;
2. reset to the beginning.

Conceptually:

```text
audio.pause()
audio.currentTime = 0
```

The ready state at the top is silent.

## 12.6 Replay of complete experience

If the user chooses to replay the complete autoplay experience from `COMPLETE`:

```text
audio = 0
experience = 0
```

and both begin again together.

---

# 13. Audio failure fallback

Audio must be an enhancement, never a prerequisite.

If:

```text
audio.play()
```

is rejected, the file cannot be decoded, the source is missing or another playback error occurs:

- the visual experience still starts;
- graphs still animate;
- scrolling still operates;
- disclosures still open;
- the page remains fully meaningful;
- no mathematical or presentation state becomes blocked;
- the failure does not crash `ExperienceController`.

The soundtrack controller may transition to:

```text
blocked
```

or:

```text
error
```

while the rest of the experience continues.

A technical error modal must not interrupt the letter.

If user-facing feedback is included, it must be quiet and non-invasive.

Example accessible status:

```text
La experiencia continúa sin audio.
```

No retry loop is required in v1.1.0.

# 14. Golden-thread halo

## 14.1 Purpose

The shared golden trajectory receives a subtle glow to strengthen the symbolic reading of the shared thread.

The effect belongs exclusively to presentation.

It does not modify:

- path coordinates;
- timing;
- mathematical values;
- SVG sampling.

## 14.2 Required visual behavior

The visible golden line remains:

- sharp;
- approximately 2 px;
- continuous;
- antique gold.

A second low-opacity visual layer may create the glow beneath it.

Conceptually:

```text
soft blurred gold stroke
        +
sharp gold stroke
```

Recommended starting range:

```text
glow stroke width: 6–8 px
opacity:           0.18–0.30
blur:              subtle
```

These values are `PROPOSED V1.1` and require visual validation.

The result should resemble:

```text
a warm luminous thread
```

and must not resemble:

```text
neon
laser
high-intensity outer glow
```

## 14.3 Implementation options

Preferred:

- SVG filter using `feGaussianBlur` and merge;
- or a duplicate presentation path beneath the shared path.

Choose the simpler implementation that preserves:

- temporal reveal;
- responsiveness;
- accessibility;
- performance.

If a duplicate path is used, it must consume the same visible temporal geometry as the sharp path.

There must not be two independent animation clocks.

# 15. Narrative timing calibration

## 15.1 New objective

The approximately 100-second silent v1.0 baseline is no longer the desired target.

v1.1.0 should allow more time for reading while remaining within the useful duration of the selected soundtrack.

Target complete automatic journey:

\[
\boxed{
1:55\text{ to }1:58
}
\]

Preferred upper boundary:

\[
\boxed{
<2:00
}
\]

The two graph durations remain:

\[
30s + 30s = 60s.
\]

All additional duration belongs to presentation.

## 15.2 Primary musical landmark

The selected soundtrack contains an important musical transition/narrative knot at approximately:

\[
0:59.
\]

The first audiovisual baseline should begin Model A approximately five seconds before that point.

Target:

\[
\boxed{
t_{A,start}\approx0:54
}
\]

Preferred validation window:

\[
\boxed{
0:52\le t_{A,start}\le0:56
}
\]

This is an audiovisual composition target, not a synchronization contract.

The experience does not dynamically correct itself if the measured value falls slightly outside this range on a device.

# 16. Proposed v1.1.0 cinematic timeline

The following is the first implementation target.

| Approx. soundtrack time | Experience |
|---|---|
| `0:00` | User opens letter; audio and experience begin |
| `0:00–0:06` | Intro |
| `0:06–0:09` | Scroll and settle on Model B |
| `0:09–0:39` | Model B animation |
| `0:39–0:42` | Hold completed Model B |
| `0:42–0:49` | Model B mathematical/narrative reading |
| `0:49–0:53` | Transition text and travel |
| `0:53–0:54` | Arrival/settle on Model A |
| `≈0:54` | Model A begins |
| `≈0:59` | Musical knot occurs shortly after Model A begins |
| `0:54–1:24` | Model A animation |
| `1:24–1:28` | Hold completed Model A |
| `1:28–1:43` | Model A mathematical/narrative reading |
| `1:43–1:48` | Scroll toward closing |
| `1:48–1:55` | Closing |
| `1:55–1:58` | Return to top and finish |
| `≈1:58` | `COMPLETE`, soundtrack reset |

This timeline is a composition baseline.

It may be adjusted during real audiovisual validation if:

- Model A continues to begin near `0:54`;
- both graphs remain exactly 30 seconds;
- reading remains comfortable;
- complete autoplay remains below approximately 2 minutes.

# 17. Reading pace

The v1.0 implementation already supports viewport-based reading of long mathematical disclosures.

v1.1.0 must recalibrate that behavior to prioritize readability over the former ~100-second target.

## 17.1 Model B

Target audiovisual window:

```text
approximately 7 seconds
```

for the automatically exposed mathematical/narrative portion after B.

The actual implementation may distribute this time between:

- disclosure opening;
- viewport travel;
- short holds.

## 17.2 Model A

Target audiovisual window:

```text
approximately 15 seconds
```

for the automatically exposed mathematical/narrative portion after A.

Model A receives more time because the disclosure is significantly denser.

## 17.3 Per-viewport pacing

The current viewport-stepped disclosure traversal may be slowed.

A reasonable first calibration is:

```text
approximately 2.2–2.5 seconds minimum per meaningful viewport step
```

instead of optimizing for the earlier shorter experience.

Exact pacing remains subject to mobile visual validation.

## 17.4 Hard priority

If there is a conflict between:

```text
exactly 1:58
```

and:

```text
content being reasonably readable
```

prefer readability as long as the total remains approximately below 2 minutes.

Do not speed up graph animations.
